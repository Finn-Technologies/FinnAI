# A/B: shorter-by-default reply prompt — 2026-10-02

Question: did the shorter-by-default edit to `finnSafetySystemPrompt`
(`lib/src/engine/prompt/prompt_formatter.dart`) lower answer quality?

- NEW: "…match the user's tone and language. Lead with the answer, then stop:
  a short reply is the default, and you go longer only when the user asks for
  depth, steps, or detail. … Avoid robotic filler, preambles, apologies, and
  repetition."
- OLD (HEAD): "…match the user's tone and language, and keep replies as long as
  the question needs. Think before you answer, … Avoid robotic filler,
  apologies, and repetition."

Method: interleaved NEW, OLD, NEW, OLD, NEW, OLD. Each run: full suite
(34 cases / 40 observations) on the Xiaomi (`ebe7291`) via `./tool/run_eval.sh`,
evaluation APK rebuilt per variant. Every run gated against the committed
`eval/baseline_Abhi-Flex1-device.json` (model LFM2.5-VL 1.6B, context 4096;
device identity matched). No baseline was rewritten; no gate was changed.

## Averages and decision

- NEW average pass rate: **0.6458**. OLD average: **0.7083**.
- Decision rule (agreed): keep NEW iff NEW avg >= OLD avg − 0.03 (0.6783) and
  NEW replies are not longer. NEW avg 0.6458 < 0.6783, and NEW median length
  49.0 toks > OLD 45.2 toks. **Both prongs fail → reverted.**
- Applied: the OLD length instruction is back in `prompt_formatter.dart`;
  the only kept NEW wording is "preambles" (not a length instruction).
  The tree now differs from HEAD by that one word. `flutter test --no-pub
  test/engine` passes (237).
- Caveat: per-variant range (NEW 0.56–0.78, OLD 0.66–0.75) dwarfs the 0.06 gap,
  so sampling noise (fresh seed per answer, temperature 0.3–0.85) cannot be
  ruled out as the whole story. OLD average clears the 0.70 floor, so no gate
  change is proposed.

## Incidental finding (fixed the same day)

Every gate-mode eval before this A/B ran with `"baseline":null`: the script
pushed the baseline to `/sdcard/Android/data/<pkg>/files`, which the app
cannot read (scoped storage denies it even for its own package — verified via
`run-as cat` → `Permission denied`). Those runs checked only the 3 absolute
gates. Fixed: `tool/run_eval.sh` stages the baseline (and `--prompts` files)
through `run-as` into internal files; `harness.dart` now logs
`FINN_EVAL_ERROR baseline not found` instead of gating silently. All 6 A/B
runs above show a loaded baseline in `FINN_EVAL_START`.
